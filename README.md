# PipelineTabularDataSynth

## Project Overview
This repository provides a modular pipeline to generate synthetic tabular data (CTGAN/TVAE variants) and evaluate
utility, privacy, and resemblance metrics across multiple datasets. It includes reusable pipeline components
(generation, sampling/rejection, and evaluation tasks) plus experiment scripts and notebooks for systematic
comparisons (epsilon sweeps, disclosure protection, and optimization studies).

Architecture overview:
- **Code vs. results separation:** core library code lives under `src/`, while heavy experiment artifacts are stored
  in a dedicated Hugging Face dataset submodule at `pipeline_tabular_data_results/`.
- **Pipeline abstraction:** `PipelineBuilder` composes generation, utility, privacy, and resemblance evaluation tasks
  into repeatable workflows.
- **Audience:** researchers and engineers running synthetic-data experiments, and reviewers who need to verify
  reported results without pulling all artifacts.

## Repository Structure
```
.
|-- src/                            # Core pipeline + evaluators
|-- experiments/                    # Scripts and notebooks (entry points)
|-- pipeline_tabular_data_results/  # Submodule: large artifacts (Git LFS)
|-- tests/                          # Unit tests

```

Lightweight vs. heavy content:
- **Lightweight code:** `src/`, `experiments/`, `tests/`, `requirements.txt`, `setup.py`, `RESULTS_STORAGE.md`.
- **Heavy artifacts:** `pipeline_tabular_data_results/` (submodule; Git LFS; do not auto-download).

## Quick Start (No Large Downloads)
To avoid downloading large Git LFS objects by default, disable LFS smudge **before cloning** and **before initializing
submodules**.

If you already have a local mirror/checkout and want a clean clone without LFS downloads:
```
GIT_LFS_SKIP_SMUDGE=1 git clone --recurse-submodules . ../pipeline_tabular_data_synth_clean
cd ../pipeline_tabular_data_synth_clean
```
If you are cloning from a remote, use the same `GIT_LFS_SKIP_SMUDGE=1` prefix with your standard `git clone` command.

For any clone (local or remote), initialize the submodule **without** pulling LFS objects:
```
GIT_LFS_SKIP_SMUDGE=1 git submodule update --init --recursive
```

Notes:
- LFS files will remain as lightweight pointer files until you explicitly pull what you need.
- Some experiment scripts expect the results tree under `experiments/pipeline_tabular_data_results/`.
  If you keep the submodule at the repo root (default), create a symlink to avoid editing scripts:
  `ln -s ../pipeline_tabular_data_results experiments/pipeline_tabular_data_results`

## Results & Large Artifacts (Hugging Face Submodule)
All heavy experiment outputs live in the `pipeline_tabular_data_results/` submodule, pinned to a specific commit
for reproducibility. The submodule is hosted at the Hugging Face dataset repo:
`https://huggingface.co/datasets/dayav/pipeline_tabular_data_results`

What lives in `pipeline_tabular_data_results/` (top-level folders):
- `data/`: train/test CSVs and dataset artifacts
- `baseline/`: baseline generator outputs
- `epsilon_comparison_heom_any*`: epsilon sweep results (weighted variants included)
- `epsilon_utility_comparison_heom_any*`: utility evaluation artifacts
- `epsilon_disclosure_protection_comparison_heom_any*`: disclosure protection outputs
- `generator_optimization/`: generator tuning artifacts
- `optuna/`: Optuna studies (pickle/json)
- `privacy_evaluation_pipeline*`: privacy pipeline outputs
- `utility_evaluation_pipeline/`: utility pipeline outputs
- `mode_collapse_correction/`: mode-collapse correction outputs
- `extra/`: analysis/plot artifacts

Why a submodule:
- Keeps the main repo lightweight and reviewable.
- Cleanly versions results independently from code.
- Allows selective download of only the artifacts needed for a given task.

Why Git LFS:
- Artifacts include large CSVs, pickles, and model files unsuitable for normal Git history.

If you do nothing after initializing the submodule:
- You will only have **LFS pointer files** (small text stubs).
- Any script/notebook that loads real data/models will fail until you pull the required artifacts.

## Selective Download Guide (CRITICAL SECTION)
**LFS pointer vs. real file**
- A pointer file is a small text stub. You can spot it by opening the file header:
```
head -n 3 pipeline_tabular_data_results/data/adult_train.csv
```
If the file begins with a line like:
```
version https://git-lfs.github.com/spec/v1
```
then you still have a pointer, not the real data.

**Inspect which files are LFS-tracked**
```
git -C pipeline_tabular_data_results lfs ls-files
```

**Download everything (discouraged)**
```
git -C pipeline_tabular_data_results lfs pull
```

**Download a specific folder**
```
git -C pipeline_tabular_data_results lfs pull --include "data/**"
```

**Download a specific file pattern**
```
git -C pipeline_tabular_data_results lfs pull --include "optuna/study_ctgan_adult.*"
```

You can combine multiple folders/patterns:
```
git -C pipeline_tabular_data_results lfs pull --include "data/**,baseline/**,epsilon_comparison_heom_any/adult_ctgan_eps_0.1/**"
```

## Disk Space & Troubleshooting
Common issues and fixes:
- **`smudge filter lfs failed`**: LFS attempted to download but failed. Fix by installing LFS and re-running a
  targeted pull, for example:
  `git lfs install` then `git -C pipeline_tabular_data_results lfs pull --include "data/**"`.
- **`No space left on device`**: Free space by removing unneeded artifacts and pruning LFS objects:
  `git -C pipeline_tabular_data_results lfs prune`.
- **Pointer files still present**: If a CSV/PKL opens as a tiny text file, pull the required artifacts, for example:
  `git -C pipeline_tabular_data_results lfs pull --include "data/**"`.
